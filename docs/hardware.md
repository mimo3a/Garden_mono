# Hardware — Smart Garden V2 (STM32L476 + FreeRTOS)

Состояние: **спецификация, утверждена 2026-10-25**. Железо V2 ещё не собрано; значения с пометкой «оценка» или `[HW]` проверяются замером и записываются сюда.
Протокол и payload — `docs/protocol.md`. Задачи — `docs/roadmap/firmware.md` (FW-3-1, FW-5-4, FW-5-5, FW-5-6).

## 1. Состав

| Блок | Где | Содержимое |
|---|---|---|
| **Главный блок** | корпус | STM32L476 (сейчас Nucleo-L476RG, см. FW-3-1), ESP32 с внешней антенной, аккумулятор Li-ion 1S, контроллер заряда с аппаратной защитой по температуре (NTC на аккумуляторе), TCA9548A, ключи питания модулей |
| **Модуль датчиков** ×0…4 | у грядки, до 3 м от главного блока | ADS1115 (адрес 0x48), 4 входа датчиков влажности с pull-down и RC-фильтром |
| **Датчик влажности почвы** ×4 на модуль | в почве, до 2 м от модуля | ёмкостный датчик, аналоговый выход |
| **Датчик воздуха** | снаружи корпуса, в вентилируемом радиационном экране | BME280 (0x76): температура, влажность, давление. От его температуры зависит защита от мороза (`docs/AI_AGENT_PLAN.md`) |
| **DS18B20** | в почве | температура почвы, 1-Wire |

**Модуль = зона.** Модуль `m` (0…3) — зона `m+1`, его каналы — `4m … 4m+3` в массиве `soil` (4 зоны × 4 датчика, `AI_AGENT_PLAN.md`). Привязку можно изменить в backend (BE-3-1).

Подключено может быть **от 0 до 4 модулей** в любых разъёмах. Отсутствующий или неисправный модуль не мешает остальным (раздел 6).

## 2. Шина I2C и адреса

```
STM32 I2C1 (PB6 SCL / PB7 SDA)
 ├─ TCA9548A 0x70 ─┬─ канал 0 ── разъём M1 ── ADS1115 0x48
 │                 ├─ канал 1 ── разъём M2 ── ADS1115 0x48
 │                 ├─ канал 2 ── разъём M3 ── ADS1115 0x48
 │                 ├─ канал 3 ── разъём M4 ── ADS1115 0x48
 │                 └─ канал 4 ── разъём AIR ── BME280 0x76
 └─ INA219 0x40 (на плате главного блока, FW-5-6)
```

| Адрес | Устройство | Примечание |
|---|---|---|
| 0x40 | INA219 | ток и напряжение входа заряда, на главной шине |
| 0x48 | ADS1115 | одинаковый во всех модулях, разделение — каналами TCA |
| 0x70 | TCA9548A | A0…A2 = GND. 0x76/0x77 не использовать — занят BME280 |
| 0x76 | BME280 | SDO = GND |

- Все модули **одинаковые** (ADDR ADS1115 = GND), модуль можно переставить в любой разъём.
- Одновременно открыт **только один** канал TCA. После опроса канал закрывается (регистр управления = 0x00).
- Зависший модуль (SDA в LOW) блокирует только свой канал TCA. Восстановление шины — 9 тактов SCL на этом канале, затем закрытие канала (FW-2-4, FW-5-4).
- Стенд без TCA (`HW_HAS_TCA9548A = 0`): ADS1115 на 0x48…0x4B прямо на I2C1, модуль `m` = адрес `0x48 + m` (см. FW-2-1).

## 3. Распиновка STM32L476

Зафиксировано в `.ioc`: USART1 PA9/PA10, I2C1 PB6/PB7, LD2 PA5, LSE PC14/PC15.
Остальные пины — **предложение**, окончательно утверждаются в CubeMX в FW-3-1 / FW-5-4 (`[CUBEMX]`). PA2/PA3 (USART2 → ST-LINK VCP) не занимать.

| Функция | Пин | Режим | Статус |
|---|---|---|---|
| UART к ESP32 TX / RX | PA9 / PA10 | USART1, 115200 8N1 | зафиксировано |
| I2C1 SCL / SDA | PB6 / PB7 | I2C, 50 кГц (раздел 5) | зафиксировано |
| LED | PA5 | GPIO out | зафиксировано |
| Присутствие модуля M1…M4 | PC6, PC8, PC9, PA8 | GPIO in, pull-up **только на время измерения** | предложение |
| Питание модуля M1…M4 (ключ) | PB12, PB13, PB14, PB15 | GPIO out, по умолчанию выключено | предложение |
| Питание TCA9548A + BME280 | PC10 | GPIO out | предложение |
| DS18B20 | PC12 | GPIO open-drain + внешний 4.7 кОм | предложение |
| Батарея (делитель 100k/100k) | PA0 | ADC1_IN5 | предложение |
| Температура аккумулятора (отдельный NTC или отвод от NTC контроллера, только чтение) | PA1 | ADC1_IN6 | предложение |
| Дополнительный запрет заряда (только для варианта с CN3791) | PC11 | GPIO out, HIGH = запрет; pull-down → при Hi-Z заряд **разрешён** | предложение |
| `CHRG` / `DONE` контроллера заряда | PB1 / PB2 | GPIO in (открытый сток, pull-up на время чтения) | предложение |

## 4. Разъёмы и кабели

### Модуль ↔ главный блок (до 3 м)

5 контактов, герметичный разъём (например GX16-5 или M12 A-coded 5-pin):

| Контакт | Сигнал | Назначение |
|---|---|---|
| 1 | VCC_SW | 3.3 В через ключ главного блока |
| 2 | GND | общий |
| 3 | SDA | I2C, канал TCA |
| 4 | SCL | I2C, канал TCA |
| 5 | PRESENT | в модуле замкнут на GND; в главном блоке — GPIO с pull-up на время измерения |

Кабель — витые пары, SDA и SCL **не в одной паре**: пары `SDA+GND`, `SCL+GND`, `VCC_SW+GND`, `PRESENT+GND` (например, CAT5e). Экран — к GND главного блока с одной стороны.
Защита на внешних линиях в главном блоке: последовательные резисторы 100 Ом на SDA/SCL, TVS-диоды на SDA, SCL, PRESENT, VCC_SW.

### Датчик влажности ↔ модуль (до 2 м)

3 контакта: VCC, GND, AOUT. Пара `AOUT+GND` витая или экранированный кабель.
На входе ADS1115: RC-фильтр (например 1 кОм + 100 нФ) и **pull-down** на GND.
Номинал pull-down подобрать по выходному сопротивлению датчика `[HW]`: он не должен заметно делить рабочий сигнал (ориентир 1 МОм; 100 кОм допустим, только если выход датчика низкоомный). Pull-down даёт около 0 В на отключённом входе — код `-3` (раздел 6).

## 5. I2C на 3 м `[HW]`

- **Старт: 50 кГц.** 100 кГц — только после замера времени фронта на всех подключённых каналах.
- **Pull-up на каждом канале TCA** (на стороне главного блока, после мультиплексора), начальный номинал 2.2 кОм к VCC_SW; на главной шине — свои pull-up 4.7 кОм.
- Бюджет ёмкости: кабель ~50–100 пФ/м → 150–300 пФ + вход модуля; предел стандарта 400 пФ. Каждый канал TCA — отдельный сегмент, ёмкости не складываются.
- Критерий: время нарастания (30 % → 70 %) ≤ 1000 нс для 100 кГц (Standard-mode), с запасом.

|---|---|---|---|---|---|---|
| 0 | | | | | | |
| 1 | | | | | | |
| 2 | | | | | | |
| 3 | | | | | | |
| 4 (AIR) | | | | | | |

## 6. Модули: питание, присутствие, отказы

### Последовательность измерения одного модуля

1. Включить pull-up на PRESENT, подождать ≥ 1 мс, прочитать. Pull-up выключить сразу после чтения: подключённый модуль замыкает PRESENT на GND, внутренний pull-up L4 (~40 кОм) тянет ~80 мкА — больше тока MCU в STOP.
2. PRESENT = HIGH (модуль не подключён) → модуль `absent`, все 4 канала — код `-1`. Питание не включать.
3. Включить VCC_SW модуля, подождать время прогрева датчиков (по даташиту датчика, ориентир 500 мс — уточнить `[HW]`).
4. Открыть канал TCA, опросить 4 канала ADS1115 в single-shot с таймаутами.
5. **Выключение строго в этом порядке:**
   1. закрыть канал TCA (регистр = 0x00);
   2. линии модуля на стороне STM/TCA — в LOW или analog (не оставлять pull-up к 3.3 В на обесточенном модуле);
   3. выключить VCC_SW.

   Иначе ADS1115 запитается паразитно через защитные диоды SDA/SCL.

Питание TCA9548A и BME280 (PC10) выключается на время сна по тем же правилам: сначала линии I2C1 в analog, затем питание.

### Таблица отказов

Источник истины статуса модуля — поле `modules` в payload; коды в `soilRaw` дублируют его и должны совпадать (`docs/protocol.md`).

| Ситуация | Как определяется | `modules[m]` | `soil` | `soilRaw` |
|---|---|---|---|---|
| Модуль не подключён | PRESENT = HIGH | `"absent"` | `null` ×4 | `-1` ×4 |
| Модуль подключён, ADS1115 не отвечает | PRESENT = LOW, NACK или таймаут I2C | `"error"` | `null` ×4 | `-2` ×4 |
| Не открывается канал TCA | NACK от TCA9548A | `"error"` | `null` ×4 | `-6` ×4 |
| Обрыв датчика | raw < `RAW_OPEN_MAX` | `"ok"` | `null` | `-3` |
| Замыкание / насыщение | raw > `RAW_SHORT_MIN` | `"ok"` | `null` | `-4` |
| Таймаут конверсии | бит OS не выставился за таймаут | `"ok"` | `null` | `-5` |
| Канал исправен | — | `"ok"` | 0…100 | 0…32767 |
| Стенд без контактов присутствия, ADS не отвечает | нельзя отличить отсутствие от отказа | `"error"` | `null` ×4 | `-2` ×4 |

Пороги `RAW_OPEN_MAX` / `RAW_SHORT_MIN` — по калибровке (FW-5-1) `[HW]`.
Ошибка одного модуля не прерывает измерение остальных; JSON отправляется всегда.
Датчик воздуха и DS18B20 при сбое дают `null` в своих полях и бит в `status`.

## 7. Питание и зарядка

### Главное требование

**Защита заряда по температуре работает аппаратно, без MCU.** STM32 может оказаться выключенным: Shutdown при критическом разряде (FW-3-5), brownout, зависание, отсутствие прошивки. Тогда его пины в Hi-Z. Если бы заряд разрешал STM, разряженный аккумулятор больше никогда бы не зарядился — устройство мертво до ручного вмешательства. Поэтому:

- заряд при нормальной температуре идёт **без участия STM**, в том числе когда STM выключен и аккумулятор разряжен;
- запрет на холоде (и перегреве) — аппаратный;
- STM только **читает** состояние (`CHRG`/`DONE`, температура) и в варианте с CN3791 может **дополнительно** запретить заряд, но не может быть единственным, кто его разрешает.

### Схема (основной вариант)

```
Разъём входа (БП 9–12 В или солнечная панель)
  → контроллер заряда с MPPT и входом NTC (BQ24650 / CN3722) ── NTC на корпусе аккумулятора
  → аккумулятор Li-ion 1S → защита аккумулятора (DW01 + MOSFET)
  → LDO 3.3 В с низким Iq → STM32, ESP32, периферия
INA219 — на входе контроллера заряда (ток и напряжение источника)
STM32 ← CHRG / DONE (чтение), ← температура аккумулятора (чтение)
```

Контроллер питается от входа (панель / БП), поэтому работает и тогда, когда аккумулятор разряжен до отключения защитой: подключение зарядного напряжения снимает состояние переразряда DW01.

### Контроллер заряда

**Основной вариант — контроллер с аппаратным NTC и MPPT** (выбор между ними — FW-3-1):

| | TI BQ24650 | Consonance CN3722 |
|---|---|---|
| Вход NTC | `TS`: окно температуры задаётся делителем от `VREF`, вне окна заряд приостанавливается | `TEMP`: NTC на GND, встроенный источник тока; по справочным данным пороги ~1.61 В / ~0.175 В — заряд приостанавливается вне окна |
| MPPT | да (вход `MPPSET`) | да |
| Внешние ключи | синхронный понижающий, внешние MOSFET | понижающий, внешний P-MOSFET |
| Что проверить по datasheet | номиналы делителя `TS` для окна 0…45 °C, ток заряда | номинал NTC и резисторов для нижнего порога 0 °C (с NTC 10 кОм по умолчанию нижний порог может не совпасть с 0 °C), ток заряда |

Пороги **0 °C (запрет заряда)** и **+45 °C** обязательно рассчитать по datasheet выбранной микросхемы и проверить замером (FW-3-1). Значения из этой таблицы — справочные, не проверенные по полному datasheet.

**Запасной вариант — CN3791** (вход 4.5–28 В, MPPT, один разъём для панели и БП). По таблице выводов (VG, GND, CHRG, DONE, COM, MPPT, BAT, CSP, VCC, DRV) **у CN3791 нет вывода NTC и вывода разрешения заряда** — полный datasheet не прочитан (страница LCSC недоступна), подтвердить. С ним нужен **аппаратный узел температурной защиты**:

```
Разъём входа → P-MOSFET (ключ входа) → CN3791 → аккумулятор
                  ↑ затвор
   компаратор с гистерезисом (nano-power, питание от входа через LDO)
       ← делитель с NTC на корпусе аккумулятора
       ← линия INHIBIT от STM (HIGH = запрет, pull-down к GND)
```

- Питание компаратора — **от входа**, а не от аккумулятора: узел работает всегда, когда есть чем заряжать, даже при полностью разряженном аккумуляторе.
- Логика: T ≥ 0 °C (с гистерезисом ~3 K: включение при ≥ +3 °C) и T ≤ +45 °C и INHIBIT = LOW → ключ открыт; иначе закрыт.
- **Состояние по умолчанию при нормальной температуре — заряд разрешён.** STM в Hi-Z → pull-down держит INHIBIT = LOW → заряд идёт.
- Обрыв NTC → делитель даёт значение «холодно» → заряд запрещён (выбрать схему делителя так, чтобы обрыв читался как выход за окно).
- STM может только **дополнительно** запретить заряд (INHIBIT = HIGH), например при неисправности, обнаруженной программно.

### Запрет заряда на холоде (обязательно)

Li-ion **нельзя заряжать ниже 0 °C** (осаждение лития на аноде, необратимая потеря ёмкости и риск короткого замыкания внутри элемента).

- NTC — на корпусе аккумулятора, а не BME280 и не DS18B20.
- Запрет: T < 0 °C и T > +45 °C; повторное разрешение после нагрева до ≥ +3 °C (гистерезис).
- Работает аппаратно (контроллер с NTC или компаратор), независимо от состояния STM.
- STM читает температуру аккумулятора и `CHRG`/`DONE`, сообщает «заряд приостановлен по температуре» битом в `status`; неисправность NTC — тоже бит в `status`.

### Что измеряет STM32

| Величина | Как | Зачем |
|---|---|---|
| Напряжение аккумулятора | делитель 100k/100k → ADC + VREFINT (FW-2-3) | защита аккумулятора (`CLAUDE.md`), `battery` в payload |
| Температура аккумулятора | NTC → ADC (только чтение; защиту делает железо) | диагностика, бит «заряд приостановлен по температуре» |
| Напряжение и ток входа | INA219 (0x40) | есть ли источник, сколько энергии приходит (FW-5-6) |
| Состояние заряда | `CHRG` / `DONE` контроллера | идёт заряд / заряжен |

Делители и NTC подключать через ключ или с большим номиналом — на время сна они не должны тянуть ток (FW-3-4).

## 9. Открытые вопросы (решаются в FW-3-1)

1. Главный блок: Nucleo-L476RG с отключённым ST-LINK или своя плата / модуль с L476.
2. ESP32: DevKit (как сейчас) или модуль WROOM на своей плате с LDO низкого Iq.
3. Контроллер заряда: BQ24650 или CN3722 с аппаратным NTC (основной вариант) либо CN3791 + аппаратный узел NTC на компараторе (запасной). Разрешение заряда только от STM — **запрещено**.
4. Ёмкость аккумулятора и мощность панели — по бюджету из раздела 8 после замера.
5. Ключи питания модулей: отдельный на каждый модуль (рекомендация — изолирует замыкание в одном кабеле) или общий.

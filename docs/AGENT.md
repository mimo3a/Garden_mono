# AGENT.md — правила исполнения ROADMAP.md

Этот файл задаёт, **как** агент выполняет задачи из `ROADMAP.md`.
Архитектура, протокол, ветки и инженерные ограничения описаны в `CLAUDE.md` в корне репозитория `Garden_mono`.

**Приоритет при конфликте:** `CLAUDE.md` > `AGENT.md` > `ROADMAP.md`.
Если задача из ROADMAP противоречит CLAUDE.md:
1. остановиться;
2. описать конфликт;
3. ждать решения Алекса.

---

## 1. Перед началом сессии
1. Прочитать `CLAUDE.md`. Если задача касается насоса, полива, агента, approvals или audit log — также прочитать `docs/AI_AGENT_PLAN.md`.
2. Прочитать `ROADMAP.md` и найти **первую** задачу со статусом `[ ]`, у которой выполнены все зависимости (`Зависит от`).
3. Прочитать все файлы из поля `Файлы` этой задачи **целиком**. Не править код по памяти и по фрагментам.

## 2. Согласование (обязательно)
- **В начале каждой фазы** кратко представить план фазы: задачи, порядок, риски. Ждать одобрения Алекса. Это требование CLAUDE.md.
- **Перед каждой задачей** с маркером `[DECISION]` или `[COORD]` отдельно согласовать решение, даже если фаза одобрена.
- Обычные задачи внутри одобренной фазы выполнять без повторного вопроса.

## 3. Маркеры задач
| Маркер | Значение | Что делает агент |
|---|---|---|
| `[HW]` | Нужна проверка на железе | Готовит код и пошаговую процедуру проверки. Ставит статус `[~]` и **не** отмечает задачу выполненной. |
| `[COORD]` | Меняется payload или протокол | Правит все затронутые компоненты (STM32, ESP32, `MqttMessageHandler.java`, frontend) в одной ветке. Если доступа к компоненту нет — фиксирует его как блокер. |
| `[DECISION]` | Нужен выбор Алекса | Предлагает 2–3 варианта с плюсами и минусами и ждёт выбора. |
| `[CUBEMX]` | Нужна правка `.ioc` | Не трогает `.ioc` вручную. Пишет Алексу точные шаги в CubeMX: что выставить и где. |

## 4. Правила работы с кодом
- **STM32CubeMX:** любые правки в сгенерированных файлах (`main.c`, `freertos.c`, `stm32l4xx_it.c`, `stm32l4xx_hal_msp.c`) — **только внутри блоков `/* USER CODE BEGIN … */ … /* USER CODE END … */`**. Код вне этих блоков будет стёрт при регенерации.
- Новая логика — по возможности в отдельных модулях (`*.c/*.h` в `STM-L476-FreeRTOS/STM_Garden_V2/Core/MyLib`), а не в `main.c`.
- **Ветки** — по модели из CLAUDE.md: `feature/<id>-<кратко>` → `develop`. В `main` напрямую не коммитить.
- **Коммит:** одна задача = одна ветка, один или несколько коммитов. Формат сообщения: `stm: P1-2 описание` (префиксы `esp:`, `backend:`, `frontend:`, `docs:` — для других компонентов).
- **Сборка:** после правки STM32 проект `STM_Garden_V2` должен собираться в STM32CubeIDE без ошибок и **без новых warnings**. Headless-сборки пока нет: если собрать нельзя, сказать об этом явно и не выдавать задачу за проверенную.
- **Запрещено** (из CLAUDE.md): прошивать устройства, деплоить на сервер, класть секреты в репозиторий.
- Каждый путь в low-power-коде должен иметь таймаут. Бесконечное ожидание (`HAL_MAX_DELAY`, `while(!flag)` без лимита) запрещено.
- Изменения формата JSON или формулы батареи — обновлять раздел payload в `CLAUDE.md` и `README.md` в той же ветке.

## 5. Статусы в ROADMAP.md
- `[ ]` — не начата
- `[>]` — в работе (агент ставит при старте)
- `[~]` — код готов, ждёт проверки на железе или решения
- `[x]` — выполнена и проверена
- `[!]` — заблокирована (причина в строке `Заметка`)

При смене статуса дописать в задачу строку:
`Заметка (ГГГГ-ММ-ДД): что сделано / ветка / коммит / что проверить`

Статус в `[x]` переводит агент только после подтверждения Алекса, если у задачи есть маркер `[HW]`.

## 6. Отчёт после задачи
Коротко:
1. Что изменено (файлы, функции).
2. Результат сборки.
3. Процедура проверки на стенде — для `[HW]`.
4. Риски и последствия для других компонентов.
5. Какая задача следующая.

## 7. Если что-то пошло не так
- Сборка сломалась и причина неочевидна → откатить свои изменения, описать проблему, поставить `[!]`.
- В ходе работы найден новый баг → **не чинить попутно**. Добавить новую задачу в конец соответствующей фазы с пометкой `(найдено при <ID>)`.
- Задача оказалась больше, чем описано → предложить разбить её на подзадачи и ждать одобрения.

# Firmware — STM32L476 + FreeRTOS

Порядок выполнения задаётся вехами в `docs/ROADMAP.md`. Правила — `docs/AGENT.md`.
Проект: `STM-L476-FreeRTOS/STM_Garden_V2/` (далее `L476/`). Плата: Nucleo-L476RG (STM32L476RGT, 1 МБ Flash, 128 КБ SRAM).

## Исходное состояние (на 2026-10-25)
- Одна задача `SensorTask` (`Core/Src/freertos.c`) раз в секунду читает 2× ADS1115 (адреса GND и VDD) под мьютексом `i2c1MutexHandle` и шлёт `{"channels":[{"dev","ch","status","raw"}…]}` по USART1 (PA9/PA10, 115200). Команд не принимает.
- `defaultTask` — heartbeat LED LD2 (PA5).
- Нет: DS18B20, батареи, сна, watchdog, приёма UART, `deviceId`, калибровки.
- Драйвер `Core/MyLib/ads1115.c` идентичен F103: `HAL_MAX_DELAY` на I2C, `HAL_Delay` на время конверсии.
- `configTOTAL_HEAP_SIZE` = 8192, нет `configCHECK_FOR_STACK_OVERFLOW` и malloc-failed hook. Timebase HAL — TIM6.
- Сборка только в STM32CubeIDE, `.ioc` ведётся в CubeMX.

## Справка для агента
- Пользовательский код — только в `USER CODE BEGIN/END` файлов `main.c`, `freertos.c`, `stm32l4xx_it.c`, `stm32l4xx_hal_msp.c`. Новые модули — в `L476/Core/App/` (логика приложения) и `L476/Core/MyLib/` (драйверы).
- В задачах FreeRTOS **нельзя** `HAL_Delay` (кроме init до старта планировщика) и `HAL_MAX_DELAY`. Ожидание — `osDelay` / таймауты очередей.
- Из ISR — только `...FromISR` API и `osMessageQueuePut(..., 0)`.
- Перед ссылкой на регистры и режимы L4 агент сверяется с RM0351 и datasheet DS10198, а не пишет по памяти. Если документа нет в репозитории — так и говорит и помечает утверждение как непроверенное.

## FW-2. Датчики и payload

- [ ] **FW-2-1. Payload V2: схема на 16 каналов** `[COORD]` `[DECISION]`
  - Зависит от: FW-1-4

  - Решено (2026-10-25): недоступный канал — `soil: null` и код `< 0` в `soilRaw` (`-1` … `-6`); статус модуля — `modules` (источник истины); `PAYLOAD_MAX_LEN = 512` байт вместе с `\n`.
  - Ещё решить: откуда `deviceId` у L476 — `#define DEVICE_ID` или только топик ESP (ESP-1-2).
  - Сделать:
    - `payload.c` — формирование JSON из структуры измерения; буфер TX 512 байт; при переполнении — не отправлять обрезанную строку (ошибка в `status`);
    - нормальное значение `soilRaw` ограничивать диапазоном 0…32767, отрицательное — только код;
    - переключатель при сборке `HW_HAS_TCA9548A`:
      - `1` — модули за TCA9548A (каналы 0…3), все ADS на 0x48, контакты присутствия (FW-5-4);

## FW-3. Питание и сон

- [ ] **FW-3-1. Архитектура питания узла L476** `[DECISION]` `[HW]`
  - Спецификация и бюджет энергии — `docs/hardware.md` (разделы 7–9). Задача доводит её до решений и схемы.
  - Проблема: Nucleo-L476RG и ESP32 DevKit не предназначены для батарейной работы — ST-LINK, AMS1117 и CP2102 потребляют в сне на порядки больше, чем MCU в STOP (оценка ~5–10 мА против десятков мкА).
  - Открытые вопросы (решить и записать в `docs/hardware.md`):
    1. Главный блок: (a) Nucleo от 3V3 с отключённым ST-LINK (UM1724); (b) своя плата / модуль с L476 и LDO с низким Iq; (c) сейчас (a), (b) отдельной задачей после M2. Рекомендация: (c).
    2. ESP32: DevKit (как сейчас) или модуль WROOM на своей плате с LDO низкого Iq.
    3. Контроллер заряда для одного разъёма «БП или солнечная панель»: (a) CN3791 (MPPT, 4.5–28 В) — по таблице выводов **нет вывода NTC и вывода разрешения**, заряд разрешает STM через ключ на входе; (b) CN3722 или TI BQ24650 — MPPT и аппаратный NTC, STM — второй уровень. Сверить по полному datasheet выбранной микросхемы.
    4. Что измеряет STM: напряжение аккумулятора (FW-2-3), температура аккумулятора (NTC), напряжение и ток входа (INA219, FW-5-6), `CHRG`/`DONE`.
    5. Бюджет энергии: ток сна, ток 16 датчиков на время измерения, ESP + Wi-Fi + TLS, ёмкость аккумулятора, мощность панели для зимы — по оценке в `docs/hardware.md`, уточнить после FW-3-2.
    6. Ключи питания модулей: по одному на модуль (рекомендация) или общий.
  - **Обязательно: запрет заряда Li-ion ниже 0 °C.** NTC на корпусе аккумулятора; разрешить при T ≥ +3 °C, запретить при T < 0 °C и выше +45 °C; ключ разрешения по умолчанию закрыт (сброс, зависание, обрыв NTC → заряд запрещён). Логика порогов — чистая функция с хост-тестом; бит в `status`. Если выбран контроллер с NTC — аппаратная защита основная.
  - Сделать: схема питания (вход → ключ разрешения → контроллер заряда → аккумулятор с защитой → LDO → MCU / ESP32 / периферия) и распиновка в `docs/hardware.md`, список модификаций платы, ожидаемые токи.
  - Проверка `[HW]`: аккумулятор с NTC в морозилке — заряд не идёт при T < 0 °C; обрыв NTC — заряд не идёт.

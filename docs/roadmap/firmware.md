# Firmware — STM32L476 + FreeRTOS

Порядок выполнения задаётся вехами в `docs/ROADMAP.md`. Правила — `docs/AGENT.md`.
Проект: `STM-L476-FreeRTOS/STM_Garden_V2/` (далее `L476/`). Плата: Nucleo-L476RG (STM32L476RGT, 1 МБ Flash, 128 КБ SRAM).

## Исходное состояние (на 2026-10-25)
- Одна задача `SensorTask` (`Core/Src/freertos.c`) раз в секунду читает 2× ADS1115 (адреса GND и VDD) под мьютексом `i2c1MutexHandle` и шлёт `{"channels":[{"dev","ch","status","raw"}…]}` по USART1 (PA9/PA10, 115200). Команд не принимает.
- `defaultTask` — heartbeat LED LD2 (PA5).
- Нет: DS18B20, батареи, сна, watchdog, приёма UART, `deviceId`, калибровки.
- Драйвер `Core/MyLib/ads1115.c` идентичен F103: `HAL_MAX_DELAY` на I2C, `HAL_Delay` на время конверсии.
- `configTOTAL_HEAP_SIZE` = 8192, нет `configCHECK_FOR_STACK_OVERFLOW` и malloc-failed hook. Timebase HAL — TIM6.
- Сборка только в STM32CubeIDE, `.ioc` ведётся в CubeMX.

## Справка для агента
- Пользовательский код — только в `USER CODE BEGIN/END` файлов `main.c`, `freertos.c`, `stm32l4xx_it.c`, `stm32l4xx_hal_msp.c`. Новые модули — в `L476/Core/App/` (логика приложения) и `L476/Core/MyLib/` (драйверы).
- В задачах FreeRTOS **нельзя** `HAL_Delay` (кроме init до старта планировщика) и `HAL_MAX_DELAY`. Ожидание — `osDelay` / таймауты очередей.
- Из ISR — только `...FromISR` API и `osMessageQueuePut(..., 0)`.
- Перед ссылкой на регистры и режимы L4 агент сверяется с RM0351 и datasheet DS10198, а не пишет по памяти. Если документа нет в репозитории — так и говорит и помечает утверждение как непроверенное.

## FW-3. Питание и сон

- [ ] **FW-3-1. Архитектура питания узла L476** `[DECISION]` `[HW]`
  - Проблема: Nucleo-L476RG не предназначена для батарейной работы — ST-LINK и стабилизатор платы потребляют на порядки больше, чем MCU в STOP.
  - Варианты:
    - (a) Nucleo от 3V3 напрямую с модификацией перемычек (отключение ST-LINK, по user manual UM1724) — быстро, но плата остаётся отладочной;
    - (b) отдельный модуль или своя плата с L476/L4 и LDO с низким Iq — правильно для финала, дольше;
    - (c) пока (a), в плане отдельной задачей (b) после M2.
  - Рекомендация: (c).
  - Сделать: схема питания (аккумулятор → защита → LDO → MCU/ADS/DS18B20/ESP32) в `docs/hardware.md`, список модификаций платы, ожидаемые токи.

- [ ] **FW-3-2. Исходный замер тока** `[HW]`
  - Зависит от: FW-3-1, FW-1-4
  - Сделать (процедура агента, замер — Алекс): ток в ожидании, при измерении, при ожидании ACK, длительность активной фазы. Через перемычку IDD (JP6 на Nucleo) или шунт. Результат — в `docs/power.md`. Это база для FW-3-3…FW-3-5.

- [ ] **FW-3-3. STOP с пробуждением по UART** `[DECISION]` `[HW]` `[CUBEMX]`
  - Зависит от: FW-3-2
  - Варианты режима (сверить с RM0351, какие периферийные блоки могут будить из какого STOP):
    - (a) STOP1 + пробуждение USART1 по старт-биту (тактирование USART1 от HSI16) — без перекладки проводов;
    - (b) STOP2 + LPUART1 — меньше ток, нужны другие пины и перекладка провода к ESP32;
    - (c) STOP2 + EXTI на RX (как на F103) — универсально, но первый байт команды теряется.
  - Варианты управления сном:
    - (a) прикладной сон: `PowerTask` при отсутствии работы останавливает планировщик и явно входит в STOP, после пробуждения восстанавливает такты и периферию;
    - (b) tickless idle FreeRTOS (`configUSE_TICKLESS_IDLE = 2`) с LPTIM1 как источником тика.
  - Рекомендация: режим (a) или (b) по результату сверки с RM0351; управление — прикладной сон (a): одно измерение в час, tickless избыточен и сложнее в отладке.
  - Требования: команда `MEASURE` после пробуждения не теряется либо гарантированно повторяется (ESP-1-3); ложное пробуждение от шума без валидной команды за 500 мс → обратно в STOP; все пути с таймаутами.
  - Проверка: 20 циклов подряд без пропусков; касание RX проводом не вызывает передачу; ток в STOP записан в `docs/power.md`.

- [ ] **FW-3-4. Периферия и GPIO перед сном** `[HW]`
  - Зависит от: FW-3-3
  - Сделать: неиспользуемые пины — analog, тактирование неиспользуемых блоков выключено; TX к ESP32 — в состоянии без утечки (сверить, как ESP32 держит RX в deep sleep); `HAL_DBGMCU_*` для STOP включать только при подключённом отладчике или в debug-сборке (урок F103); питание датчиков через ключ — если будет на схеме (FW-3-1).

- [ ] **FW-3-5. Защита аккумулятора** `[HW]`
  - Зависит от: FW-2-3, FW-3-3
  - Сделать по `CLAUDE.md`: предупреждение ниже 3400 мВ (бит в `status`), отключение после трёх подряд измерений ниже 3100 мВ — вход в Shutdown/Standby с миганием LED; значение ниже `BATTERY_FLOATING_MV` — «плавающий вход», не критическая батарея. Логика порогов — чистая функция с хост-тестом.

- [ ] **FW-3-6. IWDG и контроль задач** `[DECISION]` `[HW]`

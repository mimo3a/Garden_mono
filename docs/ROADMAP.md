## Ключевые решения, на которых построен план

1. **Целевая платформа — только STM32L476 + FreeRTOS (V2).** V1 (STM32F103) выведен из работы и не ремонтируется и не поддерживается (решение 2026-10-25); код V1 — архив в ветке `v1-f103` и релизах `v1.0.x`. Уроки F103 (отрицательная температура, ложные 100 % влажности, ложные пробуждения, батарея) учтены в задачах L476 сразу правильно.
2. **Совместимость с F103 не требуется.** Обмен STM32 ↔ ESP32 остаётся `MEASURE` / JSON / `OK`, но единственная поддерживаемая схема данных — payload V2: 16 слотов `soil` (4 модуля × 4), коды ошибок в `soilRaw`, `modules`, `air`, `fw`, `status`; ESP добавляет `sid`, `seq` и `ts` (`docs/protocol.md`). Backend, ESP и frontend не обязаны принимать payload V1; история V1 в БД остаётся и отображается.
3. **Перерыв в данных: из сада нет данных с 2026-10-05 до релиза V2** (V1 выведен из работы). Dashboard показывает устройство offline; история до 2026-10-05 сохраняется в БД. Оповещения об offline (BE-2-2) не должны срабатывать на этот перерыв.
4. **AI-агент полива начинается только после M2**, то есть когда L476 стал рабочим устройством на `main`. Так требует и `ai-agent-discovery.md` («Pre-Phase 1 prerequisite»).
5. **Доставка с подтверждением (решение 2026-10-25).** ESP отвечает STM `OK` сразу после валидного JSON; backend подтверждает запись топиком `smartgarden/{id}/ack`; неподтверждённые измерения ESP хранит в ограниченной очереди и досылает; уникальность — `deviceId + sid + seq` (`sid` — случайный идентификатор, новый после стирания NVS).
6. **Железо V2 — `docs/hardware.md`:** 0…4 одинаковых модуля датчиков за TCA9548A, модуль = зона, датчик воздуха в вентилируемом экране, запрет заряда Li-ion ниже 0 °C — аппаратно, без участия MCU.

## Обнаруженные проблемы в текущем коде (уже включены в задачи)

| Где | Проблема | Задача |
|---|---|---|
| frontend | `ONLINE_WINDOW_MS` = 30 мин при интервале измерений 60 мин — устройство половину времени показывается offline | FE-1-2 |
| backend | `null` в массиве `soil` сохраняется как `0.0`; без массива `soil` сообщение падает с исключением и молча теряется | BE-1-1 |
| ESP32 | `PubSubClient` по умолчанию держит пакет 256 байт — payload с 8 каналами и `fw`/`status` молча не опубликуется | ESP-1-1 |
| ESP32 | Приёмный буфер `Serial2` 256 байт, а JSON приходит, пока ESP подключается к Wi-Fi и не читает UART — payload V2 (до 374 байт) обрежется | ESP-1-1 |
| backend | Нет исходящего MQTT — подтвердить запись устройству нечем | BE-1-4 |
| L476 | Нет команды `MEASURE`: задача шлёт JSON каждую секунду, нет сна, батареи, DS18B20; `HAL_MAX_DELAY` и `HAL_Delay` внутри задачи | FW-1…FW-3 |
| CI | Сборка и деплой только на push в `main`, без тестов; на `develop` и PR нет проверок вообще; сборки прошивки STM32 в CI нет | OPS-0-1, FW-0-1 |
| ops | `mosquitto.conf` в репозитории: `allow_anonymous true`, порт 1883 открыт наружу без TLS — при таком же конфиге на сервере кто угодно может публиковать данные | OPS-1-2, OPS-1-3 |
| ops | Пароль БД `secret` в `docker-compose.yml`; образы только с тегом `latest`; нет бэкапов | OPS-1-1, OPS-1-4, OPS-1-5 |
| backend | Нет ни одного теста; схема БД через `ddl-auto=update` без миграций | BE-0-1, BE-0-2 |

## M1 — L476 как узел датчиков: первые данные V2

**Цель:** L476 на стенде отвечает на `MEASURE` payload V2 (`docs/protocol.md`; на стенде без TCA — до 4 ADS1115 на 0x48…0x4B, температура, батарея), данные доходят до dashboard. Питание пока от USB, без сна.
**Готово, когда:** свежее измерение L476 видно в dashboard, сбойный канал показан как «нет данных», а не 100 %; ESP32 подключается под своим MQTT-пользователем с ACL (OPS-1-2).

4. FW-1-4 — протокол `MEASURE` / `OK` на L476 `[COORD]`
5. FW-2-1 — payload V2: схема на 16 каналов `[COORD]` `[DECISION]`
6. ESP-1-1 — буферы, разбор JSON и ранний `OK` `[COORD]`
7. ESP-1-2 — топик по `DEVICE_ID` шлюза `[DECISION]`
8. OPS-1-2 — MQTT без анонимного доступа, пользователи и ACL, вместе с первой прошивкой ESP для V2 `[COORD]`

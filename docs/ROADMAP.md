# ROADMAP — Smart Garden, прошивка STM32

Правила исполнения — в `AGENT.md`. Архитектура и ограничения — в `CLAUDE.md`.
Составлено: 2026-10-25 по коду `STM/Core/Src` (ветка `main`, STM32F103) и `CLAUDE.md`.

## Допущения
- Основной объект плана — стабильная прошивка **STM32F103** (`STM/`). Фазы 1–5 делаются для неё, фаза 6 переносит результат на **STM32L476** (`develop`).
- Код ESP32, backend и frontend при составлении плана не просматривался. Задачи `[COORD]` требуют доступа ко всему репозиторию (Claude Code), а не только к `STM/Core/Src`.
- Реализация `ds18b20.c` и `ads1115.c` не просматривалась. Задачи, зависящие от них, начинаются с чтения этих файлов.
- Логика AI-агента полива и насоса **не входит** в этот план: она описана в `docs/AI_AGENT_PLAN.md`. Здесь только точка стыковки (фаза 7).

## Фаза 1 — Багфиксы F103

- [ ] **P1-1. Отрицательная температура ломает JSON** `[HW]`
  - Файлы: `main.c` (`MeasureAndDisplay`), `ds18b20.c/.h` (прочитать)
  - Проблема: формат `%d.%02d` при −0.5 °C даёт `0.-50`, при −1.25 °C — `-1.-25` или `-1.25`, в зависимости от того, как драйвер возвращает знак. Невалидный JSON отбрасывается на ESP32 или backend.
  - Сделать: выяснить контракт `DS18B20_ReadTemperatureInt`. Форматировать из одного знакового значения в сотых градуса: знак отдельно, `abs(целая).abs(дробь)`. Вынести в функцию `FormatTemperature(char*, size_t, int32_t centi)`.
  - Проверка: юнит-проверка функции на значениях −55.00, −0.50, −0.06, 0.00, 24.50, 125.00 (можно хост-тестом через gcc). На стенде — датчик в морозилке.

- [ ] **P1-2. Ошибка канала ADS1115 выглядит как 100 % влажности** `[COORD]` `[DECISION]`
  - Файлы: `moisture_sensor.c/.h`, `main.c`, ESP32 (транзит), `MqttMessageHandler.java`, `src/utils/sensorData.js`
  - Проблема: при ошибке I2C `MoistureSensor_Read` возвращает 0, а `Moisture_ToPercent(0)` даёт 100 %. `adsReady` проверяется один раз до чтения и не отражает сбой отдельного канала.
  - Варианты для решения:
    - (a) `null` в элементах `soil` и `soilRaw` для сбойного канала;
    - (b) сохранить числа, добавить битовую маску `soilErr`;
    - (c) сентинел `-1`.
  - Рекомендация: (a) — без новых полей, однозначно для frontend.
  - Сделать: `MoistureSensor_Read` возвращает `HAL_StatusTypeDef`, значение — через указатель. Backend не сохраняет измерение `soilN` для `null`. Frontend показывает «нет данных» и предупреждение.
  - Проверка: отключить один датчик или ADS → в БД нет ложных 100 %.

- [ ] **P1-3. Ложные пробуждения от шума на RX** `[COORD]` `[HW]`
  - Файлы: `main.c` (`HAL_GPIO_EXTI_Callback`, `EnterStopMode`, основной цикл), `ESP/src/main.cpp`
  - Проблема: любой falling edge на PA10 сразу ставит `measure_flag`, поэтому измерение и передачу запускает шум, а не команда. Сама `MEASURE\n` (~0.7 мс) теряется, пока поднимаются HSE и PLL.
  - Сделать:
    - **STM32:** EXTI ставит только `wake_flag`. После реинициализации UART ждать строку `MEASURE` до 500 мс (`WAKE_CMD_TIMEOUT_MS`); если её нет — сразу обратно в STOP.
    - **ESP32:** после старта отправить байт-преамбулу `\n`, выдержать 50 мс, затем `MEASURE\n`. Повторить до 3 раз, пока не придёт JSON.
    - Обратная совместимость: новая ESP со старой STM работает (лишний `\n` игнорируется). Порядок прошивки описать в отчёте.
  - Проверка: 20 циклов подряд без пропусков. Касание RX проводом не вызывает передачу (LED не мигает дважды).

- [ ] **P1-4. Единый порог «плавающего» входа батареи** `[DECISION]`
  - Файлы: `main.c`
  - Проблема: в коде порог 2400 мВ (отсечка DW01A), в CLAUDE.md — «< ~2800 мВ = floating input». Значения расходятся.
  - Сделать: `#define BATTERY_FLOATING_MV`, значение согласовать (по умолчанию 2800 по CLAUDE.md). Обновить комментарий и CLAUDE.md, если выбрано другое значение.

- [ ] **P1-5. Компенсация VDD через VREFINT** `[HW]` `[COORD]`
  - Зависит от: P1-4
  - Файлы: `main.c` (`ReadBatteryMillivolts`, `MX_ADC1_Init` USER CODE), `CLAUDE.md`, `README.md`
  - Проблема: расчёт предполагает VDD = 3300 мВ. Когда аккумулятор подходит к 3.3–3.4 В, LDO выходит из стабилизации, VDD падает, и показания врут как раз в зоне low и critical.
  - Сделать: дополнительно измерять `ADC_CHANNEL_VREFINT` (включить `TSVREFE`, sampling 239.5 cycles). Формула: `VDD = 1200 * 4095 / raw_vref`, затем `Vbat = raw_bat * VDD * 2 / 4095`. Номинал VREFINT F103 — 1.20 В (разброс 1.16–1.24 В, заводской калибровки на F1 нет). Опционально — калибровочный коэффициент `#define`.
  - Формулу в разделе payload CLAUDE.md обновить. Поле `battery` остаётся в мВ, поэтому `[COORD]` здесь только для документации.
  - Проверка: лабораторный БП 3.0–4.2 В с шагом 0.1 В, сравнение с мультиметром, погрешность ≤ 50 мВ.

- [ ] **P1-6. Ожидание ACK без busy-wait**
  - Файлы: `main.c` (основной цикл)
  - Проблема: до 30 с пустой цикл на 72 МГц — лишний расход на каждом цикле, где ESP не прислала ACK.
  - Сделать: внутри цикла ожидания `__WFI()` (Sleep mode; разбудят прерывания UART и SysTick). Таймаут 30 с сохранить.
  - Готово, когда: поведение не изменилось, ток при ожидании ниже (замер — в P3-1).

- [ ] **P1-7. Переполнение строки RX**
  - Файлы: `main.c` (`HAL_UART_RxCpltCallback`)
  - Проблема: при длине больше 31 символа хвост отбрасывается, и обрезанная строка может совпасть с командой.
  - Сделать: флаг `rx_overflow`; строка с переполнением отбрасывается целиком при `\n`.

## Фаза 2 — Надёжность

- [ ] **P2-1. Сторожевой механизм** `[DECISION]`
  - Проблема: IWDG на F103 **нельзя остановить в STOP** — при 60-минутном сне он сбросит MCU (максимальный таймаут около 26 с).
  - Варианты:
    - (a) без IWDG: все пути с таймаутами + сброс в обработчиках ошибок (P2-2);
    - (b) IWDG + пробуждение по RTC alarm каждые ~20 с для перезагрузки сторожа (больше расход);
    - (c) IWDG только на время активной фазы — на F1 невозможно, вариант отпадает.
  - Рекомендация: (a).

- [ ] **P2-2. Сброс вместо зависания**
  - Зависит от: P2-1
  - Файлы: `main.c` (`Error_Handler`, USER CODE), `stm32f1xx_it.c` (`HardFault_IRQn 0`, `MemoryManagement_IRQn 0`, `BusFault_IRQn 0`, `UsageFault_IRQn 0`)
  - Сделать: перед сбросом сохранить причину в backup-регистр (`BKP->DR1`), затем `NVIC_SystemReset()`. При старте прочитать причину, добавить её в стартовое сообщение и очистить регистр.
  - Готово, когда: искусственный `Error_Handler()` приводит к перезапуску и сообщению с причиной.

- [ ] **P2-3. Восстановление шины I2C** `[HW]`
  - Файлы: новый `i2c_recovery.c/.h`, `main.c` (`EnterStopMode`, вызов перед `MX_I2C1_Init`)
  - Проблема: если ADS1115 удерживает SDA (сброс посреди транзакции или помеха), `HAL_I2C` вечно в BUSY. Плюс известная errata F1 (ES096, «I2C analog filter may provide wrong value, locking BUSY flag»).
  - Сделать:
    - если SDA = LOW — PB6/PB7 в GPIO open-drain, 9 тактов SCL, STOP-условие;
    - процедура `SWRST` по errata при `BUSY` после init;
    - вызывать при старте, после пробуждения и при ошибке `ADS1115_IsReady`.
  - Проверка: замкнуть SDA на GND во время измерения → следующий цикл восстанавливается без сброса питания.

- [ ] **P2-4. Ограничить все UART-таймауты**
  - Файлы: `main.c`
  - Сделать: заменить `HAL_MAX_DELAY` в стартовых сообщениях на конечный таймаут (100 мс). Проверить, что ESP32 игнорирует не-JSON строки `ADS1115 OK` / `not found` (прочитать `ESP/src/main.cpp`); если нет — перевести эти сообщения в JSON или убрать.

- [ ] **P2-5. Проверка `HAL_ADC_PollForConversion`**
  - Файлы: `main.c` (`ReadBatteryMillivolts`)
  - Сделать: при не-`HAL_OK` отбрасывать выборку. Если все 8 выборок неудачны — вернуть 0, что трактуется как floating (порог P1-4), а не как critical.
